## 1. 产品概述

智家能是一套面向普通家庭的多模态能源决策系统。电表通常只告诉住户「这个月用了多少度」；本产品把监测做成决策，回答三件事：

1. **为什么贵**——今日电量、峰谷结构、第一耗电设备是谁；
2. **哪笔是浪费**——凌晨异常启动、低占用仍高功率等，用规则说清楚原因；
3. **今晚关哪一档**——给出可勾选的节能建议，并由「管家宝强」模拟执行，对比执行前后的电量与电费。

系统以**四路传感时序**（电力、室内温湿度、占用、天气）为输入，经对齐、预测、异常解释、策略与执行闭环，形成可演示、可复现、可诚实讲边界的完整产品。

演示家庭锁定为：成都四口之家 · 夏季 · 连续约 30 天 · 演示时刻 **2026-08-19 20:30**。

## 2. 目标用户

| 用户 | 痛点 | 产品如何帮到 |
| --- | --- | --- |
| 城市家庭住户 | 账单难懂、不知今晚改什么 | 总览回放 + 执行单 + 管家一句话 |
| 宿舍 / 合租人群 | 待机与异常浪费看不见 | 异常解释器按规则归因 |
| 能源服务 / 物业演示方 | 需要可移植决策内核 | 标准表灌库 + 缺模态降级 + 验证户导入轨 |
| 评委 / 技术评审 | 要看真实指标与边界 | 模型实验舱落盘 MAE/RMSE/MAPE/R²，F1 主动展示 |

**非目标：** 不替代缴费电表；不做无标签总表 NILM；现场不控制真实物理插座（模拟执行）。

## 3. 核心功能

### 3.1 智能总览

- 今日用电、截至此时电费、能源评分、第一耗电设备；
- 24 小时功率回放（实际 / 优化 / 占用），高峰时段可视化；
- 四路传感对齐条：室内温度进模型，室外天气不进，光照与 CO₂ 只解释。

### 3.2 能耗分析与设备

- 分路电量占比（演示日空调约 41%、热水器约 22%、冰箱约 12%）；
- 单设备功率曲线；占比来自分路汇总，**不是**总表盲拆。

### 3.3 能耗预测

- XGBoost 递推未来 6 / 24 小时负荷；
- 绿色带宽按真实 RMSE 绘制；
- **只报** MAE、RMSE、MAPE、R²，并对照「昨天同时段」「近 7 日同时段平均」；不用 100−MAPE 当准确率。

### 3.4 异常解释器

- 主：规则（凌晨用水电、无人仍高功率、连续照明等）；
- 辅：Isolation Forest 只打分；
- 演示户植入 **03:17 热水器** 可回放、可归因；
- 主动展示 F1=0.35（标注 13 / 检出 27），结论以规则为准，不做自动断电。

### 3.5 AI 节能建议

- 多目标：收益 × 可行性 × 接受度 × 舒适度；
- Top 策略示例：空调 24℃ → 26℃；
- 优化前后电量、电费、碳排与削峰曲线同屏对比；节能量按**本户今日电量**估算。

### 3.6 管家宝强

- 白话指令：汇报一下、执行今晚节能方案、晚安、出门、空调 26 度、点头；
- 模拟改当前开关与设定温度，**不改写**历史用电曲线；
- 硬约束：拒绝关闭冰箱。

### 3.7 生活系统

- 电价时钟（峰 / 平 / 谷）；
- 今晚任务、电网削峰邀约、谷电预约。

### 3.8 数据来源与模型实验舱

- 传感合同表：采样、单位、是否进模型、演示户 / 验证户对照；
- 缺一路降级；插座 / 温湿度 CSV 按同一字段替换；
- 实验舱并排展示演示户与验证户指标；验证户周均值优于模型时诚实提示。

### 3.9 使用说明

- 家庭用户入口 `/guide`；右下角「3 分钟演示」默认三幕并锁定演示户。

## 4. AI 的角色与价值

| 模块 | 算法 / 机制 | AI 在产品中的角色 | 价值边界 |
| --- | --- | --- | --- |
| 能耗预测 | XGBoost（TimeSeriesSplit 三折） | 告诉住户「今晚 / 明天会不会更高」 | 只报落盘指标；带宽=RMSE，不是保证线 |
| 异常检测 | Isolation Forest + 规则引擎 | IF 打分；规则给「为什么怪」 | F1=0.35 主动展示；上线以规则为准 |
| 负荷识别 | RandomForest（有标签 1h 窗） | 有分路标签时的设备窗分类 | **不是**总表 NILM；验证户无标签则不适用 |
| 节能策略 | 规则多目标引擎 | 生成今晚可执行动作并模拟收益 | 按本户估算，不对全市/碳中和空头承诺 |
| 管家 / 助手 | 规则意图 + 可选白话解释 | 把建议变成动作；解释已算结果 | 大模型**不算指标**；现场为模拟控制 |

**AI 价值一句话：** 把「看不懂的度」变成「说得清的原因」和「今晚可执行的一档」，并用可复现实验证明预测与异常的能力与短板。

## 5. 技术实现思路

### 5.1 总体架构

```text
传感四路 → 5 分钟对齐 / 缺模态降级 → SQLite
                ↓
         FastAPI 业务服务
                ↓
    ┌───────────┼───────────┐
    ▼           ▼           ▼
 预测模型    异常+规则     策略/管家
 (XGBoost)  (IF+规则)    (规则引擎)
    └───────────┬───────────┘
                ▼
     React 可视化 + 三幕演示 + 使用说明
```

### 5.2 技术栈

- **前端：** React + TypeScript + Vite + Ant Design + ECharts  
- **后端：** Python + FastAPI + SQLAlchemy + Pydantic  
- **AI：** XGBoost / Scikit-learn（Isolation Forest、RandomForest）  
- **数据：** 默认 SQLite；演示 CSV 灌标准表  

### 5.3 数据与两户设计

| 户 | 用途 | 说明 |
| --- | --- | --- |
| 演示户 `user_id=1` | 现场主演示 | 完整四路；稳定复现 03:17 |
| 验证户 `user_id=2` | 迁移与诚实对照 | 公开负荷风格或插座导出；缺占用则摘特征；预测变差为预期 |

导入脚本：`scripts/import_real_home.py`（`plug.csv` / `env.csv` 等）。

### 5.4 预测特征（演示户 16 列）

滞后功率、滚动均值、室内温湿度、占用、小时、星期、是否周末等；**不含**室外天气。验证户缺模态时走降级特征集。

### 5.5 关键实验指标（落盘）

**演示户预测：** MAE 110.76 W · RMSE 234.51 W · MAPE 20.34% · R² 0.9369；昨天同时段 MAPE 23.01%；近 7 日同时段 MAPE 55.36%。  

**验证户预测：** MAPE 25.09% · R² 0.8922；近 7 日同时段均值 MAPE 23.95%，**优于 XGBoost**（诚实展示）。  

**异常（演示户）：** P 0.2593 · R 0.5385 · F1 0.35 · 标注 13 / 检出 27。  

**负荷识别（有标签窗）：** Accuracy 0.9513 · macro-F1 0.9515。  

**演示日结构：** 约 18.73 kWh；空调升温 24→26℃ 为 Top 策略。

### 5.6 实现流程

`generate_demo_data` → `init_db` → `train_models` 落盘 joblib 与 metrics.json → 启动 FastAPI + Vite → 浏览器打开 127.0.0.1:5174。

## 6. 应用场景示例

### 场景 A：工作日晚高峰（20:30）

住户打开总览，看到今日已用电量与空调占比。系统提示高峰电价窗口；策略建议空调升至 26℃；管家执行后展示电费对比。

### 场景 B：凌晨异常巡检（03:17）

异常解释器标出热水器非常规启动：功率偏离来自插座，占用低来自门磁/作息，时段来自时钟。住户理解「这笔浪费」后，可在策略中关闭夜间加热逻辑（模拟）。

### 场景 C：出门与安全底线

住户对管家说「我出门了」关闭非刚需；若说「关掉冰箱」，系统拒绝，保证食品安全底线。

### 场景 D：电网削峰邀约

生活系统收到削峰邀约，一键应下后按节能方案执行，体现家庭侧需求响应演示能力。

### 场景 E：换户 / 接真传感

将插座与温湿度导出放入 `data/raw/real_home_01/`，按合同导入验证户；缺占用则降级，不在页面假装精度不变。

## 7. 产品边界与诚实声明

1. 四路均为**传感时序**，不是图像或语音。  
2. 演示含过程模型；验证户默认可为公开曲线重建，**勿宣称已接真实家庭电表**（除非已灌真实 CSV）。  
3. 负荷识别 ≠ 总表 NILM。  
4. 异常 F1=0.35，上线以规则为准。  
5. 预测不用 100−MAPE 报准确率；不对标虚构全市平均。  
6. 管家为模拟控制，不改历史曲线，不接真插座。
