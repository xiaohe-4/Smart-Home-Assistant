## 1. 方案设计

### 1.1 最初构想

家庭电表通常只给总电量。用户不知道为什么贵、哪里浪费、今晚能做什么。项目要把「监测」做成「决策」，并且把建议交到可执行的管家动作上。

### 1.2 需求

| 用户问题 | 产品回答 |
| --- | --- |
| 为什么耗电？ | 分路占比 + 峰谷结构 + 占用/室温相关 |
| 哪里浪费？ | 异常检测 + 凌晨待机 + 低占用仍运行 |
| 怎么节能？ | 多目标策略 + 模拟前后对比 + 管家执行 |

约束：10 日内可演示；允许高质量仿真数据；不自研大模型；不要求真实控制物理电器。

### 1.3 技术路线

多模态时序对齐 → 特征工程 → XGBoost 预测 / Isolation Forest 异常 / RandomForest 负荷识别 → 规则策略 → FastAPI → React 可视化 → 管家执行层。

大模型只解释，不算指标。

### 1.4 架构

前端 React + TS + Vite + Ant Design + ECharts；后端 FastAPI + SQLAlchemy + SQLite；AI 为 scikit-learn / XGBoost。数据间隔 5 分钟，演示户为成都四口之家、夏季、30 天。

### 1.5 功能规划

总览、能耗、设备、预测、异常、洞察、策略、管家、生活系统、数据来源、模型实验、助手、画像、使用说明。

- 预测：MAE 95.91 W，RMSE 203.30 W，MAPE 17.52%，R² 0.9525，准确率 82.48%（100-MAPE），样本 696

## 3. 实验测试

实验方案见 `scripts/train_models.py`。验证：TimeSeriesSplit 三折；异常对照脚本植入点；负荷识别为有标签窗口分类。结果以 `models/metrics.json` 与 `data/processed/experiment_results.json` 为准，详见 `docs/实验结果.md`。

接口与引擎测试：`pytest tests/test_api.py tests/test_ai.py`。开发后期记录为 12 passed 量级（随用例增加）。

对比原则：不把 LLM 输出当准确率；不把检出条数当异常准确率；不对标虚构的全市平均，只对标本户近 30 日。

## 4. 问题排查与解决（节选）

| 问题 | 分析 | 方案 | 验证 |
| --- | --- | --- | --- |
| 浏览器 ERR_CONNECTION_REFUSED | Vite 只听 IPv6 localhost，链接被拼进中文 | 绑定 127.0.0.1:5174，strictPort | 本机 5174 打开总览 |
| 总览整页空白 | Promise.all 一路失败全挂 | allSettled | 单接口失败仍可看其他模块 |
| 雷达「舒适」恒为 82 | 前端写死 | 按室内温度相对 26℃ 计分 | 洞察页出现计算说明 |
| 负荷识别有模型无页面 | joblib 未上屏 | `/models` + 诚实文案 | 展示 0.9513 且标明非 NILM |
| 管家把 W 读成字母 | TTS 读英文单位 | 口播改「瓦」，朗读前替换 kW/kWh | 汇报口播含「瓦」 |
| 口播呆板 | 默认声线 + 逐位读数字 | 优先自然声线，数字转中文 | 刷新后汇报更顺 |
| 后端改代码不生效 | uvicorn 无 reload | 改 Python 后重启 | 新接口 200 |
